# 1. نظرة عامة على المشروع — Project Overview

## ما هو PlanCraft AI؟

PlanCraft AI هو تطبيق يساعد المستخدم على تحويل فكرة المشروع إلى خطة عملية منظمة باستخدام الذكاء الاصطناعي.

بدلًا من أن يحصل المستخدم على إجابة عامة داخل محادثة، يستطيع إدخال تفاصيل مشروعه، ثم يرسل النظام الطلب إلى Workflow يعالجه، وينشئ خطة منظمة، ويحفظ النتيجة في قاعدة البيانات لتتمكن الواجهة من عرضها.

يجمع المشروع بين ثلاث أدوات رئيسية:

- **Lovable:** بناء واجهة التطبيق وتجربة المستخدم.
- **Supabase:** تخزين طلبات المشاريع والخطط الناتجة وإدارة حالة المعالجة.
- **n8n Cloud:** تنسيق خطوات التنفيذ وربط قاعدة البيانات بالـ AI Agent.

يمثل المشروع تطبيقًا عمليًا لمفهوم **System Integration**؛ إذ لا تعمل الأدوات بصورة منفصلة، بل تتعاون لتكوين نظام واحد.

## المشكلة التي يعالجها المشروع

عندما يمتلك شخص فكرة مشروع، قد يواجه صعوبة في تحويلها إلى خطوات واضحة، مثل:

- تحديد الهدف الفعلي للمشروع.
- تقسيم العمل إلى مراحل.
- تحديد الإجراءات التي ينبغي تنفيذها.
- اكتشاف المخاطر المحتملة.
- تقدير المدة اللازمة للتنفيذ.
- معرفة الخطوة التالية التي ينبغي البدء بها.

يهدف PlanCraft AI إلى تنظيم هذه المعلومات في خطة عملية يمكن للمستخدم مراجعتها والاستفادة منها.

## القيمة التي يقدمها المشروع

**From Project Idea to Structured Action Plan.**

من فكرة أولية إلى خطة منظمة تتضمن:

1. ملخصًا للمشروع.
2. الهدف الرئيسي.
3. مراحل التنفيذ.
4. إجراءات مقترحة.
5. المخاطر وطرق الحد منها.
6. مدة تقديرية للتنفيذ.

> ملاحظة: الخطة التي ينشئها الذكاء الاصطناعي هي اقتراح قابل للمراجعة، وليست ضمانًا لنجاح المشروع أو لصحة كل تقديراته.

# 2. أهداف التعلم — Learning Objectives

بعد إكمال المشروع، ينبغي أن تكون المتدربة قادرة على:

1. بناء تطبيق باستخدام AI App Builder.
2. تصميم قاعدة بيانات مناسبة لاحتياجات التطبيق.
3. فهم العلاقة بين Frontend وBackend وDatabase.
4. إرسال طلبات HTTP باستخدام Webhook.
5. ربط تطبيق ويب مع Workflow خارجي.
6. نقل البيانات بين الأنظمة باستخدام JSON.
7. استخراج البيانات من قاعدة البيانات داخل n8n.
8. استخدام AI Agent لإنشاء مخرجات منظمة.
9. تطبيق Structured Output Parser.
10. حفظ مخرجات الذكاء الاصطناعي في قاعدة البيانات.
11. إدارة حالة الطلب خلال مراحل المعالجة.
12. اختبار التكامل من البداية إلى النهاية.
13. اكتشاف الأخطاء وتحديد موضعها.
14. مراعاة أساسيات Security وData Integrity.

الهدف ليس مجرد إنشاء واجهة جميلة أو تشغيل AI Agent.

الهدف هو بناء نظام متكامل يمكن تتبع البيانات فيه من لحظة إدخال الطلب حتى حفظ النتيجة وعرضها للمستخدم.

# 3. المعمارية العامة — System Architecture

يتكون النظام من ثلاثة أجزاء رئيسية.

## 3.1 Lovable — Application Layer

مسؤول عن واجهة المستخدم وتجربة الاستخدام.

يتيح للمستخدم:

- إدخال بيانات المشروع.
- إرسال الطلب.
- معرفة حالة المعالجة.
- الاطلاع على الخطة الناتجة.

## 3.2 Supabase — Data Layer

مسؤول عن تخزين البيانات.

يحتوي المشروع على جدولين رئيسيين:

- `project_requests`
- `project_plans`

الجدول الأول يحتفظ بطلب المستخدم، بينما يحتفظ الجدول الثاني بالخطة التي تم إنشاؤها.

## 3.3 n8n Cloud — Automation Layer

مسؤول عن تنفيذ Workflow الخاص بتوليد الخطة.

يستقبل الطلب عبر Webhook، ويستخرج بيانات المشروع من Supabase، ثم يرسلها إلى AI Agent، ويحفظ النتيجة، ويحدّث حالة الطلب.
