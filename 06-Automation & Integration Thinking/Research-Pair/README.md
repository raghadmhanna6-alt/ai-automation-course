# 🧭 Research Topics

## 01. Integration Patterns — How Systems Communicate

**الفكرة:** استكشاف الأنماط المختلفة التي تستخدمها الأنظمة للتواصل وتبادل البيانات، وفهم كيفية اختيار نمط الاتصال المناسب.

**ابدأن الاستكشاف من:**
- [Microsoft — Cloud Design Patterns](https://learn.microsoft.com/en-us/azure/architecture/patterns/)
- [AWS — Asynchronous Request-Reply Pattern](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/async-request-reply.html)

**ركّزن على فهم:**
- ما المقصود بـ Integration Pattern؟
- ما الفرق بين Synchronous وAsynchronous Communication؟
- ما الفرق بين Request–Response وEvent-Driven Communication؟
- ما الفرق بين الاتصال المباشر والاتصال عبر وسيط؟
- كيف تختلف أنماط الاتصال من حيث زمن الاستجابة والاعتمادية وطبيعة العمليات؟

**سؤال البحث:**

ما أنماط الاتصال المستخدمة في الأنظمة الحديثة، وكيف نختار النمط المناسب وفق طبيعة العملية ومتطلباتها؟

**اكتشفن أيضًا:**

كيف تتواصل الأنظمة عندما تكون العملية طويلة، أو عندما لا يكون النظام المستقبِل متاحًا لحظة إرسال الطلب؟

**المخرج المطلوب:** مقارنة مختصرة بين ثلاثة أنماط اتصال، مع توضيح أهم خصائص كل نمط ومتى يُستخدم.

---

## 02. APIs & HTTP — The Language of Web Communication

**الفكرة:** اكتشاف كيفية تواصل التطبيقات والخدمات عبر الويب، وفهم العلاقة بين API وHTTP والبيانات المتبادلة.

**ابدأن الاستكشاف من:**
- [MDN — An Overview of HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Overview)
- [Postman Learning Center](https://learning.postman.com/)

**ركّزن على فهم:**
- ما هو API؟ وما المقصود بـ API Endpoint؟
- ما هو HTTP؟ وما دوره في الاتصال؟
- ما الفرق بين GET وPOST وPUT وPATCH وDELETE؟
- ما الفرق بين Request وResponse؟
- ما دور Headers وBody وStatus Codes؟
- هل كل API يستخدم HTTP؟
- كيف تساعد API Documentation المطورين على فهم طريقة استخدام الخدمة؟

**سؤال البحث:**

كيف تعمل APIs في الأنظمة الحديثة، وما العلاقة بين واجهة API وبروتوكول HTTP والبيانات التي تنتقل بين الأنظمة؟

**اكتشفن أيضًا:**

كيف يمكن استخدام أدوات مثل Postman لاستكشاف API وفهم استجاباته دون الحاجة إلى بناء تطبيق كامل؟

**المخرج المطلوب:** رسم توضيحي لدورة HTTP Request–Response، مع شرح دور API وHTTP وEndpoint.

---

## 03. Webhooks & Event-Driven Automation

**الفكرة:** استكشاف كيفية استخدام Webhooks لإرسال البيانات تلقائيًا عند وقوع أحداث معينة، وكيف تختلف هذه الآلية عن الطرق التقليدية للحصول على البيانات.

**ابدأن الاستكشاف من:**
- [n8n — Webhook Node Documentation](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/)
- [Webhook.site](https://webhook.site/)

**ركّزن على فهم:**
- ما هو Webhook؟
- ما المقصود بـ Event وPayload؟
- كيف يستقبل Webhook البيانات؟
- ما الفرق بين Webhooks وPolling؟
- ما العلاقة بين Webhooks وHTTP؟
- لماذا تحتاج بعض الأنظمة إلى التحقق من مصدر Webhook؟
- ما الفرق بين Test Endpoint وProduction Endpoint؟

**سؤال البحث:**

كيف تتيح Webhooks للأنظمة الاستجابة للأحداث تلقائيًا، وما الفرق بينها وبين قيام النظام بطلب البيانات بشكل متكرر؟

**اكتشفن أيضًا:**

كيف تُستخدم Webhooks في أنظمة الدفع الإلكتروني، والمتاجر، وأدوات إدارة العملاء، وخدمات الأتمتة؟

**المخرج المطلوب:** مخطط يوضح دورة حياة Webhook، من وقوع الحدث إلى استقبال البيانات ومعالجتها.

## 04. Authentication, Authorization & Secrets Management

**الفكرة:** استكشاف كيفية حماية الاتصالات بين الأنظمة والتحكم في هوية الجهات المتصلة والصلاحيات الممنوحة لها.

**ابدأن الاستكشاف من:**
- [OWASP — Secrets Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)
- [OWASP — Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)
- [Supabase — Edge Functions Secrets](https://supabase.com/docs/guides/functions/secrets)

**ركّزن على فهم:**
- ما الفرق بين Authentication وAuthorization؟
- ما المقصود بـ API Keys وBearer Tokens وOAuth؟
- ما هو Webhook Secret؟
- كيف تختلف طرق المصادقة عن بعضها؟
- لماذا يجب حماية الأسرار البرمجية؟
- ما الفرق بين تخزين الأسرار في Frontend وBackend؟
- لماذا لا تعني المصادقة امتلاك صلاحية الوصول إلى جميع البيانات؟

**سؤال البحث:**

كيف تتحقق الأنظمة من هوية الجهات التي تتصل بها، وكيف تتحكم في الصلاحيات وتحمي المعلومات الحساسة؟

**اكتشفن أيضًا:**

ما الفرق بين API Key وOAuth؟ ولماذا قد لا يكون استخدام API Key ثابت مناسبًا لجميع أنواع الاتصالات؟

**المخرج المطلوب:** جدول يقارن بين ثلاث آليات للمصادقة أو إدارة الوصول، مع توضيح استخدامات كل منها واعتباراتها الأمنية.

## 05. Data Contracts, JSON Schema & Schema Mapping

**الفكرة:** استكشاف كيفية تحديد شكل البيانات المتبادلة بين الأنظمة، وضمان توافق الحقول وأنواع البيانات ومعانيها.

**ابدأن الاستكشاف من:**
- [JSON Schema](https://json-schema.org/)
- [JSON — Official Website](https://www.json.org/json-en.html)

**ركّزن على فهم:**
- ما المقصود بـ Data Contract؟
- ما هو JSON Schema؟
- كيف نحدد الحقول المطلوبة والاختيارية؟
- ما الفرق بين Validation وTransformation؟
- ما المقصود بـ Schema Mapping؟
- كيف نتعامل مع القيم المفقودة وأنواع البيانات غير الصحيحة؟
- كيف يؤثر تغيير شكل البيانات على الأنظمة المرتبطة؟
- ما الفرق بين البيانات الصحيحة من حيث الشكل والبيانات الصحيحة من حيث المعنى؟

**سؤال البحث:**

كيف تضمن الأنظمة توافق البيانات المتبادلة بينها، وما المشكلات التي قد تحدث عندما تختلف توقعات النظام المرسل عن النظام المستقبِل؟

**اكتشفن أيضًا:**

كيف يساعد JSON Schema على وصف البيانات والتحقق من بنيتها؟ وما الفرق بين التحقق من صحة بنية البيانات والتحقق من صحة محتواها؟

**المخرج المطلوب:** مثال يوضح Data Contract، مع مقارنة بين Validation وTransformation وSchema Mapping.

## 06. Server-side Functions, Middleware & Edge Computing

**الفكرة:** اكتشاف كيفية تنفيذ المنطق البرمجي على الخادم، ودور الدوال الوسيطة في ربط الأنظمة، والتعرّف على مفهوم Edge Computing.

**ابدأن الاستكشاف من:**
- [Supabase — Edge Functions](https://supabase.com/docs/guides/functions)
- [Cloudflare — What Is Edge Computing?](https://www.cloudflare.com/learning/serverless/glossary/what-is-edge-computing/)

**ركّزن على فهم:**
- ما الفرق بين Frontend وBackend؟
- ما المقصود بـ Server-side Function؟
- ما هي Middleware؟
- ما هي Supabase Edge Functions؟
- ما الفرق بين Serverless Functions وEdge Functions؟
- كيف تستقبل الدالة طلبًا وتنفذ منطقًا برمجيًا ثم تتصل بخدمة أخرى؟
- ما دور الدوال التي تعمل على الخادم في حماية الأسرار؟
- ما المقصود بـ Edge Computing؟ وما علاقته بمكان تنفيذ العمليات؟

**سؤال البحث:**

كيف تساعد Server-side Functions وMiddleware على بناء تكامل بين الأنظمة، وما الفرق بين تنفيذ المنطق على الخادم وتنفيذه داخل المتصفح؟

**اكتشفن أيضًا:**

لماذا تُسمى بعض الدوال Serverless رغم أنها تعمل على خوادم؟ وما الذي يميز Edge Functions عن أشكال التنفيذ الأخرى؟

**المخرج المطلوب:** مخطط يقارن بين Frontend وBackend وServer-side Functions وEdge Functions، مع توضيح العلاقة بينها.

## 07. Workflow Orchestration & Distributed Systems

**الفكرة:** استكشاف كيفية تنسيق العمليات التي تتوزع على عدة خدمات وأنظمة، وفهم التحديات التي تظهر عندما لا تكون جميع الخطوات داخل تطبيق واحد.

**ابدأن الاستكشاف من:**
- [n8n Documentation](https://docs.n8n.io/)
- [Microsoft — Cloud Design Patterns](https://learn.microsoft.com/en-us/azure/architecture/patterns/)

**ركّزن على فهم:**
- ما المقصود بـ Workflow Orchestration؟
- ما الفرق بين Orchestration وChoreography؟
- ما المقصود بـ Distributed Systems؟
- كيف تُنسَّق العمليات التي تعتمد على عدة خدمات؟
- ما الفرق بين تنفيذ Workflow خطي وWorkflow يحتوي على Branching؟
- كيف تنتقل البيانات بين الخطوات؟
- لماذا تحتاج الأنظمة الموزعة إلى تحديد مسؤولية كل خدمة؟
- ما التحديات التي تظهر عندما تنجح خطوة وتفشل خطوة أخرى؟

**سؤال البحث:**

كيف يمكن تنسيق عملية تتوزع على عدة أنظمة، وما التحديات التي تجعل إدارة العمليات الموزعة مختلفة عن تنفيذ سلسلة من الخطوات داخل برنامج واحد؟

**اكتشفن أيضًا:**

ما الفرق بين Orchestration وChoreography؟ ومتى يكون من المناسب أن يدير مكوّن مركزي تسلسل العمليات، ومتى يكون التواصل قائمًا على الأحداث بين الخدمات؟

**المخرج المطلوب:** مخطط يقارن بين Orchestration وChoreography، مع مثال يوضح الفرق بينهما.

## 08. Asynchronous Processing, Queues & Event-Driven Architecture

**الفكرة:** استكشاف طرق إدارة العمليات الطويلة، ومعالجة الأحداث، والتعامل مع الطلبات التي لا يمكن تنفيذها فورًا.

**ابدأن الاستكشاف من:**
- [AWS — Asynchronous Request-Reply Pattern](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/async-request-reply.html)
- [RabbitMQ Tutorials](https://www.rabbitmq.com/tutorials)

**ركّزن على فهم:**
- ما الفرق بين Synchronous وAsynchronous Processing؟
- ما هي Message Queue؟
- ما الفرق بين Queue وEvent؟
- كيف تساعد Message Queues على فصل الأنظمة عن بعضها؟
- ما المقصود بـ Event-Driven Architecture؟
- ما الفرق بين قبول الطلب وإكمال معالجته؟
- كيف يمكن معالجة عدد كبير من الطلبات دون تنفيذها جميعًا في اللحظة نفسها؟

**سؤال البحث:**

كيف تساعد المعالجة غير المتزامنة وقوائم الرسائل على إدارة العمليات الطويلة، وتقليل الاعتماد المباشر بين الأنظمة؟

**اكتشفن أيضًا:**

ما الدور الذي تلعبه أدوات مثل RabbitMQ في تنظيم الرسائل بين الخدمات؟ وكيف تختلف Message Queue عن Webhook؟

**المخرج المطلوب:** رسم يقارن بين الاتصال المتزامن، والمعالجة غير المتزامنة، واستخدام Message Queue.

## 09. Retries, Idempotency & Duplicate Prevention

**الفكرة:** استكشاف كيفية تصميم عمليات تتحمل أخطاء الاتصال وإعادة المحاولة دون التسبب في آثار مكررة غير مقصودة.

**ابدأن الاستكشاف من:**
- [Stripe — Idempotent Requests](https://docs.stripe.com/api/idempotent_requests)
- [AWS — Retry with Backoff Pattern](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/retry-backoff.html)

**ركّزن على فهم:**
- لماذا تفشل طلبات الاتصال؟
- ما الفرق بين Retry وTimeout؟
- ما المقصود بـ Idempotency؟
- كيف تختلف إعادة الطلب عن إنشاء عملية جديدة؟
- ما المقصود بـ Idempotency Key؟
- ما هو Exponential Backoff؟
- لماذا لا تكون إعادة المحاولة آمنة دائمًا؟
- كيف يمكن أن تنشأ سجلات مكررة رغم أن النظام يبدو أنه يعالج الطلبات بشكل صحيح؟

**سؤال البحث:**

كيف نصمم العمليات بحيث تتعامل مع إعادة المحاولة بأمان، وتقلل احتمال تنفيذ الإجراء نفسه أكثر من مرة؟

**اكتشفن أيضًا:**

كيف تستخدم الخدمات المالية مفهوم Idempotency لمنع تكرار العمليات عند إعادة إرسال الطلبات؟ وما الفرق بين منع تكرار الطلب ومنع تكرار الأثر الناتج عنه؟

**المخرج المطلوب:** مقارنة بين Retry وExponential Backoff وIdempotency، مع مثال يوضح متى نحتاج إلى كل منها.

## 10. Integration Testing, Observability & Distributed Tracing

**الفكرة:** استكشاف كيفية اختبار التكامل بين الأنظمة، وتتبع الطلبات عبر الخدمات المختلفة، وفهم أسباب الأخطاء.

**ابدأن الاستكشاف من:**
- [Postman Learning Center](https://learning.postman.com/)
- [n8n — Executions](https://docs.n8n.io/workflows/executions/)
- [OpenTelemetry Documentation](https://opentelemetry.io/docs/)

**ركّزن على فهم:**
- ما الفرق بين Unit Testing وIntegration Testing وEnd-to-End Testing؟
- ما المقصود بـ Observability؟
- ما الفرق بين Logs وMetrics وTraces؟
- ما هو Distributed Tracing؟
- كيف نتتبع طلبًا ينتقل عبر عدة خدمات؟
- ما دور Correlation ID أو Trace ID؟
- كيف تساعد أدوات مثل Postman على اختبار واجهات الاتصال؟
- لماذا لا يكفي نجاح طلب HTTP لإثبات نجاح العملية كاملة؟

**سؤال البحث:**

كيف نختبر الأنظمة المترابطة، ونتتبع الطلبات بين خدمات متعددة، ونحدد موضع الخطأ عندما لا نحصل على النتيجة المتوقعة؟

**اكتشفن أيضًا:**

كيف يساعد OpenTelemetry على جمع معلومات التتبع والمراقبة من أنظمة مختلفة؟ وما الفرق بين تسجيل الأخطاء وتتبع رحلة الطلب عبر الخدمات؟

**المخرج المطلوب:** مخطط يوضح الفرق بين Logs وMetrics وTraces، مع مثال يبيّن كيف تساعد كل منها في اكتشاف مشكلة مختلفة.

# 🎤 مشاركة نتائج البحث

بعد انتهاء وقت البحث، تُشارك كل مجموعة أهم ما اكتشفته مع بقية المجموعات.

تركّز المشاركة على ثلاثة أسئلة:

1. ما أهم فكرة جديدة اكتشفها البحث؟
2. ما المشكلة التي تساعد التقنية أو المفهوم على حلها؟
3. ما المعلومة التي تغيّر فهمنا لكيفية تصميم الأنظمة أو ربطها؟

**الوقت المقترح: 3 دقائق لكل مجموعة.**

الهدف هو مشاركة المعرفة الجديدة، وليس استعراض جميع تفاصيل الأداة أو إعادة شرح المفاهيم الأساسية المعروفة.

## 💡 تذكّرن

ليس الهدف أن نحفظ أسماء التقنيات أو أن نستخدم أكبر عدد ممكن من الأدوات.

الهدف أن نفهم **كيف تتواصل الأنظمة، ولماذا تختلف طرق الاتصال، وكيف تُنظَّم البيانات، وتُحمى الاتصالات، وتُنسَّق العمليات، وتُكتشف الأخطاء.**

كلما اتسعت معرفتنا بهذه المفاهيم، أصبحت قدرتنا أفضل على فهم تقنيات جديدة، وتقييم الخيارات المتاحة، واختيار الحل المناسب للمشكلة بدلًا من الاعتماد على وصفات جاهزة.

**نحن لا نبحث لنتعلّم أداة جديدة فقط؛ بل لنوسّع فهمنا الهندسي لكيفية بناء أنظمة مترابطة.**
