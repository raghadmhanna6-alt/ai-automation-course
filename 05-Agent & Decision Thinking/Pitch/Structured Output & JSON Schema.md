🧩 Structured Output & JSON Schema
## تنظيم مخرجات الذكاء الاصطناعي والتحقق من صلاحيتها

---

## 🎯 1. هدف البحث

كيف نتحقق من أن البيانات التي يستخرجها AI Agent صالحة للاستخدام في نظام آخر، بدلًا من الاعتماد على نص غير منظم؟

يهدف البحث إلى فهم كيفية تنظيم مخرجات الذكاء الاصطناعي، وتحديد شكل البيانات المطلوبة، والتحقق من صحتها قبل إرسالها إلى أنظمة أخرى مثل Google Sheets.

## 📦 2. ما هو Structured Output؟

**Structured Output** هو جعل مخرجات الذكاء الاصطناعي تتبع بنية محددة مسبقًا، بدلًا من إرجاع نص حر.

- ❌ **نص غير منظم:** العميل أحمد، يريد شقة في غزة بميزانية 50,000 دولار.
- ✅ **مخرجات منظمة:** بيانات موزعة على حقول واضحة باستخدام JSON.

## 📝 3. ما هو JSON؟

JSON اختصار لـ **JavaScript Object Notation**، وهو تنسيق شائع لتمثيل البيانات وتبادلها بين التطبيقات.

مثال:

```json
{
  "full_name": "أحمد محمد",
  "budget": 50000
}
```

### 🔤 أنواع البيانات الأساسية

- `String`: نص.
- `Number`: رقم.
- `Boolean`: قيمة منطقية (`true` أو `false`).
- `Object`: مجموعة من الحقول.
- `Array`: قائمة من القيم.
- `Null`: قيمة فارغة صريحة.

يجب تخزين رقم الهاتف كنص للحفاظ على الصفر في بدايته.

## 🔍 4. ما هو JSON Schema؟

**JSON Schema** هو معيار يصف بنية بيانات JSON والقواعد التي يجب أن تلتزم بها.

يتيح لنا تحديد:

- 🏷️ أسماء الحقول.
- 🔠 أنواع البيانات.
- ✅ الحقول المطلوبة.
- 📏 القيود المفروضة على القيم.
- 🚫 الحقول الإضافية غير المسموح بها.

### 💡 الفرق بين JSON وJSON Schema

| JSON | JSON Schema |
|---|---|
| يحتوي على البيانات الفعلية. | يصف شكل البيانات وقواعدها. |
| يمثل المعلومات. | يساعد على التحقق من مطابقتها للقواعد. |

## ⚙️ 5. لماذا نستخدم JSON Schema؟

### 🧪 تبسيط التحقق والاختبار
اكتشاف الأخطاء والبيانات غير المتوافقة مع القواعد المحددة.

### 🔄 تسهيل تبادل البيانات
توحيد شكل البيانات لتسهيل نقلها بين الأنظمة المختلفة.

### 📝 توثيق البيانات
توضيح أسماء الحقول وأنواعها، مما يسهل فهمها والتعامل معها.

### 🛠️ دعم الأدوات والمكتبات
إمكانية استخدام أدوات ومكتبات متعددة للتحقق من البيانات بلغات برمجة مختلفة.

## 🏠 6. تطبيق الفكرة على مشروع وكيل العقارات

يحتاج AI Agent إلى جمع بيانات العملاء وتنظيمها قبل إرسالها إلى Google Sheets.

### 📋 الحقول المطلوبة

| الحقل | النوع | الوصف |
|---|---|---|
| `full_name` | String | اسم العميل |
| `contact_number` | String | رقم الهاتف |
| `property_type` | String | نوع العقار |
| `budget` | Number | الميزانية |
| `preferred_location` | String | الموقع المفضل |

### 📦 مثال على البيانات المتوقعة

```json
{
  "full_name": "أحمد محمد",
  "contact_number": "0591234567",
  "property_type": "apartment",
  "budget": 50000,
  "preferred_location": "غزة"
}
```

### 📏 قواعد التحقق

- التأكد من وجود جميع الحقول المطلوبة.
- التحقق من أن كل قيمة تتبع نوع البيانات المحدد.
- تحديد القيم المسموح بها لنوع العقار باستخدام `enum`.
- التأكد من أن الميزانية أكبر من صفر.
- منع الحقول الإضافية عند الحاجة باستخدام `additionalProperties`.

## 🧩 7. مثال مبسط على JSON Schema

```json
{
  "type": "object",
  "properties": {
    "full_name": {
      "type": "string",
      "minLength": 1
    },
    "contact_number": {
      "type": "string"
    },
    "property_type": {
      "type": "string",
      "enum": ["apartment", "house", "land"]
    },
    "budget": {
      "type": "number",
      "exclusiveMinimum": 0
    },
    "preferred_location": {
      "type": "string",
      "minLength": 1
    }
  },
  "required": [
    "full_name",
    "contact_number",
    "property_type",
    "budget",
    "preferred_location"
  ],
  "additionalProperties": false
}
```

### 🔎 أهم الخصائص

- `type`: يحدد نوع البيانات.
- `properties`: يحدد الحقول وقواعدها.
- `required`: يحدد الحقول الإلزامية.
- `enum`: يحدد القيم المسموح بها.
- `minLength`: يحدد الحد الأدنى لطول النص.
- `exclusiveMinimum`: يشترط قيمة أكبر من حد معين.
- `additionalProperties`: يتحكم في السماح بالحقول الإضافية.

## 🔄 8. كيف نتحقق من البيانات؟

يمكن تصور سير العمل كالتالي:

1. 💬 استقبال بيانات العميل.
2. 🤖 استخراج المعلومات باستخدام AI Agent.
3. 📦 تنظيم المخرجات بصيغة JSON.
4. 🔍 التحقق من البيانات باستخدام JSON Schema.
5. ⚠️ معالجة البيانات الناقصة أو غير المتواففقة مع القواعد.
6. 📊 إرسال البيانات التي اجتازت التحقق إلى Google Sheets.

### 🧪 مثال على خطأ

إذا كانت الميزانية `"خمسون ألفًا"` بدلًا من `50000`، فسيفشل التحقق لأن القيمة نص وليست رقمًا.

**ملاحظة:** مطابقة المخطط لا تعني أن المعلومات صحيحة واقعيًا؛ فقد يكون رقم الهاتف غير صحيح رغم توافقه مع القواعد.

## 🔗 9. JSON Mode وStructured Outputs

- **JSON Mode:** يساعد على إنتاج مخرجات بصيغة JSON، لكنه لا يضمن وحده الالتزام بمخطط محدد.
- **Structured Outputs:** يساعد على جعل المخرجات مطابقة لمخطط محدد عند دعم الأداة لهذه الخاصية واستخدام الإعدادات المناسبة.

تختلف الخصائص المدعومة حسب الأداة أو النموذج المستخدم.

## 💡 10. أهم ما تعلمته

- Structured Output ينظم مخرجات الذكاء الاصطناعي.
- JSON يمثل البيانات في حقول واضحة.
- JSON Schema يحدد شكل البيانات والقواعد المطلوبة.
- Validation يتحقق من توافق البيانات مع القواعد.
- التحقق قبل الإرسال يقلل أخطاء التكامل بين الأنظمة.

## 🎯 11. الخلاصة

لضمان صلاحية بيانات AI Agent للاستخدام في نظام آخر، نحدد شكل المخرجات باستخدام JSON، ونصف الحقول والقواعد باستخدام JSON Schema، ثم نتحقق من البيانات قبل إرسالها.

في مشروع وكيل العقارات، يساعد ذلك على تنظيم بيانات العملاء والتحقق من الحقول المطلوبة وأنواعها قبل إرسالها إلى Google Sheets، مما يقلل أخطاء التنسيق ويحسن موثوقية سير العمل الآلي.
