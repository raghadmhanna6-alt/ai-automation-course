# TaskBridge — Lovable Build Prompt

## 1. Project Overview

Build an AI-powered web application called TaskBridge.

**Tagline:** Turn Unclear Requests into Clear, Actionable Plans.

TaskBridge helps users transform unclear, incomplete, or unorganized requests into structured requirements and practical action plans.

The application should be simple, professional, responsive, and easy to use.

## 2. Main Objective

Create a working application that allows users to submit requests, analyze their content using AI, identify missing information, ask clarification questions when necessary, and generate structured action plans.

Do not present simulated AI results as real AI processing. Connect a genuine AI service through a secure backend when credentials and integration are available.

## 3. User Interface

Create a clean and professional interface with:

- A clear TaskBridge logo or text-based brand.
- A home page explaining the application's purpose.
- A request submission form.
- A request analysis results section.
- A clarification questions section.
- A structured action plan view.
- Clear loading, error, and empty states.
- Responsive layouts for desktop, tablet, and mobile.

Use consistent typography, spacing, accessible colors, and clear navigation.

## 4. Request Submission

Provide a form where users can enter:

- Request title.
- Detailed request description.
- Optional project context.
- Optional deadline or constraints.

Validate required fields before submission. Display understandable error messages for missing or invalid information.

## 5. AI-Powered Request Analysis

Analyze the user's request to identify:

- Main objective.
- Required outcomes.
- Important requirements.
- Constraints and deadlines.
- Missing information.
- Ambiguities or potential misunderstandings.

The AI must not invent facts, deadlines, budgets, or requirements. Clearly distinguish information provided by the user from suggestions generated by AI.

## 6. Clarification Questions

When essential information is missing, generate relevant clarification questions.

Allow the user to review and answer these questions before generating the final plan.

Avoid asking unnecessary questions when the request is already clear enough.

## 7. Action Plan Generation

Generate a structured action plan containing:

- Plan title.
- Summary of the request.
- Key requirements.
- Ordered implementation steps.
- Expected outcomes.
- Outstanding questions or assumptions.

Keep the plan practical, readable, and relevant to the original request.

## 8. Suggested Application Workflow

1. The user opens TaskBridge.
2. The user submits a request.
3. The application validates the input.
4. The AI analyzes the request.
5. The application displays missing information and clarification questions when necessary.
6. The user provides additional details.
7. The AI generates a structured action plan.
8. The user reviews the result.

## 9. Database and Supabase

Before implementing database changes, inspect the existing Supabase schema and authentication configuration.

Use the documented proposal in `database-schema.md` as a reference, not as permission to overwrite an existing database.

If persistence is required, store requests, clarification questions, action plans, and tasks using appropriate relationships.

Requirements:

- Use UUID primary keys where appropriate.
- Add foreign keys and suitable constraints.
- Enable Row Level Security for user-specific tables.
- Ensure authenticated users can access only their own private records.
- Validate ownership when creating or updating related records.
- Preserve existing data and working features.
- Use safe, additive migrations.
- Do not expose private API credentials or the Supabase service-role key in frontend code.

Do not create unnecessary tables or duplicate existing functionality.

## 10. AI Integration and Error Handling

Use a real AI model through a secure server-side integration.

Store API credentials in appropriate server-side secrets. Never hardcode secrets in client-side code or commit them to GitHub.

Handle:

- Missing API configuration.
- Network failures.
- Invalid AI responses.
- Empty requests.
- Excessively long input.
- Loading states and retry options.

If AI integration is not configured, clearly explain that setup is required instead of pretending a real analysis occurred.

## 11. Accessibility and Responsive Design

Ensure that:

- Forms have clear labels.
- Buttons have understandable names.
- Text is readable.
- Keyboard navigation works where applicable.
- Error messages are visible and understandable.
- Layouts adapt to mobile and desktop screens.

## 12. Testing Requirements

Test the following scenarios:

1. A clear, complete request.
2. An incomplete request that needs clarification.
3. An ambiguous request.
4. Empty or invalid form input.
5. A long request.
6. An AI service error or unavailable connection.
7. Successful action plan generation.
8. Saving and retrieving records, if persistence is implemented.
9. Attempts to access another user's private records.
10. Responsive behavior on mobile and desktop.

Record actual results and fix identified issues before claiming the application is complete.

## 13. Implementation Instructions

Before making changes:

1. Inspect the existing project files and application structure.
2. Identify existing features and integrations.
3. Review the current database schema and authentication setup.
4. Reuse existing components and functionality where possible.
5. Implement changes incrementally.
6. Avoid destructive database operations.
7. Test the finished functionality.

Do not replace the entire project if an existing implementation can be improved.

## 14. Expected Deliverable

Deliver a functional TaskBridge application that helps users convert unclear requests into structured, actionable plans.

The application should include a usable interface, genuine AI integration when configured, appropriate validation and error handling, and secure data access when persistence is enabled.

The implementation must be tested, and any unfinished integrations or limitations must be documented honestly.
